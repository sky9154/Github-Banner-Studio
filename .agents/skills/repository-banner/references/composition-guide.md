# Composition Guide

First confirm what the product actually does. Then choose graphics that express its function, brand, or input/output relationship. The examples below are prompts for reasoning, not required templates.

| Product type | Possible visual relationships | Evidence to confirm |
| --- | --- | --- |
| Typography tool | Glyphs, typesetting, text geometry, glyph transformations | Actual output formats and font features |
| Audio tool | Waveforms, timelines, acoustic structure | Actual recording, synthesis, or conversion flow |
| Image tool | Image structure, cropping, input/output comparison | Image operations the tool actually performs |
| Data analysis | Data relationships, charts, classification structure | Actual metrics, dimensions, and analytical capabilities |
| AI system | A process or structure tied to the model's actual function | Model task, inputs, and results; do not invent a network architecture |
| Developer tool | Inputs, outputs, transformations, and module relationships | Actual interface and development workflow |

Choose a text-led, graphic-led, split, diagonal, modular, or centered composition based on the content. Use the grid and hierarchy to make whitespace and proportion support reading.

Do not default every banner to a large title on the left, a logo on the right, and a thin rule along the bottom. Review existing Studio work and compare title placement, logo scale, graphic language, and visual center. Give each project a distinct visual cue while allowing a product family to share a coherent identity.

Record the reason for the direction in the brief—for example, “Text transformation is the product's core, so letterforms lead the composition.” “It looks technical” is not a functional rationale. If product information is thin, use restrained project-name typography or an existing logo, note the gap, and do not invent a feature graphic.
